# MailBatch — Complete Setup & Configuration Guide

Covers everything needed to run Phases 1-2 now and the settings later phases depend on.

## 1. Requirements

| Item | Version / notes |
|---|---|
| PHP | 8.3+ with extensions: `mbstring, xml, dom, curl, zip, gd, fileinfo, openssl, pdo_mysql, tokenizer, ctype, json, bcmath` (`zip`, `xml`, `gd` are needed by Laravel Excel) |
| Composer | 2.x |
| MySQL | 8.0+ (or MariaDB 10.6+) |
| Web server | Nginx or Apache (or `php artisan serve` for local use) |
| Process manager | Supervisor (production queue worker) |
| Node/NPM | **Not required.** Bootstrap and jQuery load from CDN with SRI hashes. |

Check: `php -v`, `php -m`, `composer -V`, `mysql --version`.

## 2. Create the Laravel 12 project

```bash
composer create-project laravel/laravel:^12.0 mailbatch
cd mailbatch
composer require maatwebsite/excel:^3.1
```

## 3. Copy MailBatch files

Copy the contents of the delivered `mailbatch-through-phase2` folder over the project root
(it contains `app/`, `bootstrap/app.php`, `config/mailbatch.php`, `database/`, `resources/views/`,
`public/assets/`, `routes/`, `tests/`). Allow it to overwrite `bootstrap/app.php`,
`app/Http/Controllers/Controller.php`, `app/Providers/AppServiceProvider.php`,
`database/factories/UserFactory.php` and `routes/web.php`.

## 4. Create the database

```sql
CREATE DATABASE mailbatch CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'mailbatch'@'localhost' IDENTIFIED BY 'use-a-long-random-password';
GRANT ALL PRIVILEGES ON mailbatch.* TO 'mailbatch'@'localhost';
FLUSH PRIVILEGES;
```

## 5. Configure `.env`

```dotenv
APP_NAME=MailBatch
APP_ENV=local                # production on the live server
APP_DEBUG=true               # MUST be false in production
APP_URL=http://localhost:8000
APP_TIMEZONE=Asia/Kolkata    # optional, pick your timezone

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=mailbatch
DB_USERNAME=mailbatch
DB_PASSWORD=your-db-password

SESSION_DRIVER=database
SESSION_LIFETIME=120
QUEUE_CONNECTION=database
CACHE_STORE=database

LOG_CHANNEL=daily
LOG_LEVEL=info               # never "debug" in production

# MailBatch
MAILBATCH_MAX_BATCH_SIZE=50
MAILBATCH_DEFAULT_DAILY_LIMIT=500
MAILBATCH_MAX_RETRIES=3
MAILBATCH_UPLOAD_MAX_KB=5120
MAILBATCH_MAX_ROWS=5000
MAILBATCH_DELAY_SECONDS=2
MAILBATCH_QUEUE=mailbatch
MAILBATCH_REGISTRATION_ENABLED=false
MAILBATCH_ADMIN_NAME="Administrator"
MAILBATCH_ADMIN_EMAIL=admin@yourdomain.com
MAILBATCH_ADMIN_PASSWORD=    # empty = a random password is printed once when seeding
```

Notes
- Laravel's own `MAIL_*` settings are **not used** for campaigns: each campaign uses the SMTP account configured in the app (Phase 4).
- `APP_KEY` (already generated by `create-project`) encrypts saved SMTP passwords. **Back it up.** If it changes, stored SMTP passwords become unreadable. If missing: `php artisan key:generate`.

## 6. Migrate and seed

```bash
php artisan migrate
php artisan db:seed
```

The seeder creates the admin (password printed once if you left it empty) and default system settings.
Outside production it also creates `demo@example.com` / `password` with a demo campaign.
Skip demo data with `APP_ENV=production`. To seed only the admin: `php artisan db:seed --class=AdminSeeder`.

## 7. Run locally

```bash
php artisan serve              # terminal 1 -> http://localhost:8000
# no queue worker terminal needed: sending runs from the browser (see section 18)
php artisan test               # optional, runs the Phase 2 feature tests
```

Sign in at `/login`. Self-registration is disabled; create users via seeder/admin (admin UI in Phase 8), or set
`MAILBATCH_REGISTRATION_ENABLED=true` temporarily and run `php artisan config:clear`.

## 8. Private storage (Excel uploads & exports)

Uploads and exports use the default `local` disk (`storage/app/private`), which is **not** web accessible.
Do **not** run `storage:link` for these files. Ensure the web user can write:

```bash
chmod -R ug+rwX storage bootstrap/cache
chown -R www-data:www-data storage bootstrap/cache      # Linux production
```

## 9. PHP settings (php.ini)

```ini
upload_max_filesize = 6M
post_max_size = 8M
memory_limit = 256M
max_execution_time = 60
expose_php = Off
```

Restart PHP-FPM / Apache afterwards. Keep these above `MAILBATCH_UPLOAD_MAX_KB` (5 MB by default).

## 10. Nginx virtual host (production)

```nginx
server {
    listen 80;
    server_name mailbatch.example.com;
    root /var/www/mailbatch/public;
    index index.php;
    client_max_body_size 6M;

    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    location / { try_files $uri $uri/ /index.php?$query_string; }

    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
    }

    location ~ /\.(?!well-known).* { deny all; }
}
```

Then enable HTTPS (for example `certbot --nginx -d mailbatch.example.com`). Apache users: point `DocumentRoot` to `public/` and enable `mod_rewrite` (`AllowOverride All`).

## 11. Production `.env` hardening

```dotenv
APP_ENV=production
APP_DEBUG=false
APP_URL=https://mailbatch.example.com
LOG_LEVEL=warning
SESSION_SECURE_COOKIE=true
SESSION_SAME_SITE=lax
SESSION_ENCRYPT=true
```

Behind a proxy/load balancer, enable `trustProxies` in `bootstrap/app.php` with your proxy IPs.
Optimise after every deploy:

```bash
composer install --no-dev --optimize-autoloader
php artisan migrate --force
php artisan config:cache && php artisan route:cache && php artisan view:cache
php artisan queue:restart
```

## 12. Queue worker under Supervisor (NOT needed any more - see section 18)

`/etc/supervisor/conf.d/mailbatch-worker.conf`:

```ini
[program:mailbatch-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /var/www/mailbatch/artisan queue:work database --queue=mailbatch,default --sleep=3 --tries=1 --timeout=90 --max-time=3600
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
user=www-data
numprocs=1
redirect_stderr=true
stdout_logfile=/var/www/mailbatch/storage/logs/worker.log
stopwaitsecs=3600
```

```bash
sudo supervisorctl reread && sudo supervisorctl update && sudo supervisorctl start mailbatch-worker:*
```

Keep `numprocs=1` and `--tries=1`: sending stays sequential, and a failed email is never automatically re-sent (retries are explicit user actions, which is part of duplicate protection). The worker `--timeout` (90) must be larger than `config('mailbatch.queue.job_timeout')` (60).

## 13. Optional: self-host Bootstrap/jQuery

The layouts load Bootstrap 5.3.3, Bootstrap Icons and jQuery 3.7.1 from CDNs. To avoid third-party requests, download
those files into `public/assets/vendor/` and change the `<link>`/`<script>` URLs in `layouts/app.blade.php` and `layouts/guest.blade.php`.
(No NPM build is involved.)

## 14. Verification checklist

1. `php artisan migrate:status` shows all migrations as "Ran".
2. `/login` loads; wrong passwords are throttled after 5 attempts.
3. After login, Dashboard shows six cards; they refresh every 15 s.
4. Create a campaign: batch size above 50 is rejected.
5. Another user's campaign URL returns 403.
6. `php artisan test` passes.
7. `storage/` is not reachable from the browser.

## 15. Troubleshooting

| Symptom | Fix |
|---|---|
| `Class "Maatwebsite\Excel..." not found` | `composer require maatwebsite/excel:^3.1`, then `composer dump-autoload` |
| 419 Page Expired | Clear cookies; check `APP_URL`, `SESSION_DOMAIN`, HTTPS/`SESSION_SECURE_COOKIE` match |
| 500 after deploy | `php artisan config:clear && php artisan cache:clear`, then check `storage/logs` and permissions |
| Table `jobs`/`sessions`/`cache` missing | Run `php artisan migrate` (Laravel's default migrations create them) |
| Changes to `.env` ignored | `php artisan config:clear` (and restart the queue worker) |
| Login route `register` 404 | Set `MAILBATCH_REGISTRATION_ENABLED=true`, then `php artisan config:clear` and `route:clear` |

## 16. Sending (Phase 6)

- `.env`: `QUEUE_CONNECTION=database`, `CACHE_STORE=database` (the per-recipient lock uses the cache), and a correct
  `APP_URL` (it is used to build the unsubscribe links inside emails sent by the queue worker).
- No worker process is needed: sending runs from the browser (section 18).
- After deploying new code: `php artisan queue:restart`.
- `QUEUE_CONNECTION=sync` is refused in production: it would send inside the web request.
- Check queue health: `php artisan queue:failed` and `storage/logs`.

## 17. Final steps (Phase 8)

**Scheduler** (one cron line; runs the recovery safety net every 5 minutes and nightly cleanup):

```
* * * * * cd /var/www/mailbatch && php artisan schedule:run >> /dev/null 2>&1
```

**Migrate** `php artisan migrate` (adds the permanent daily counter table).

**Admin area** `/admin`: users (create, role, disable, personal daily limit, password reset), SMTP accounts (enable/disable),
campaigns (view/pause), email logs, failed emails, system settings. Users change their own password under Account.

**Settings precedence** Admin > Settings values override `.env` defaults. The batch size can never exceed
`MAILBATCH_HARD_MAX_BATCH_SIZE` (default 50). Queue workers pick up changes within about 5 minutes (or run `php artisan queue:restart`).

**Content-Security-Policy** is enforced by default. If a custom page of yours breaks, test with `MAILBATCH_CSP=report`
(browser console shows violations without blocking), then fix or add `nonce="{{ request()->attributes->get('csp_nonce') }}"` to inline scripts.

**Go-live checklist**

1. `APP_ENV=production`, `APP_DEBUG=false`, HTTPS, `SESSION_SECURE_COOKIE=true`, correct `APP_URL`.
2. `php artisan migrate --force`, `php artisan db:seed --class=AdminSeeder`, sign in and change the admin password (Account).
3. Queue worker under Supervisor running; cron line above installed.
4. `php artisan config:cache && php artisan route:cache && php artisan view:cache`.
5. `storage/` writable, not web-accessible; `.env` not web-accessible.
6. Back up the database **and** `APP_KEY` (needed to decrypt SMTP passwords).
7. Send a test email from the composer to yourself; confirm the unsubscribe link works.
8. Run `php artisan test` on a staging copy.

**Responsible use** MailBatch is built for permission-based outreach: it keeps sender identification and an unsubscribe link,
enforces per-user daily limits and batch sizes, and has no feature to evade provider limits or spam filtering. Respect each
provider's sending policy and the anti-spam laws that apply to your recipients.

## 18. Sending without artisan (browser-driven worker)

No `queue:work`, no Supervisor, no cron and no `mailbatch:work` are needed any more.

- **Start sending** / **Retry** queue the batch, then the page calls `POST /campaigns/{id}/work` in a loop. Each call
  sends e-mails for about `MAILBATCH_WORK_SECONDS` (default 15) and returns. When the campaign's queue is empty the loop
  stops by itself and the campaign becomes Ready / Completed.
- **One queue per campaign** (`mailbatch-c{id}`) and one lock per campaign: campaigns never block or mix with each other.
- Keep the progress page open while sending. If you close it, sending pauses; opening the progress page again resumes it
  automatically (the page sees that jobs are still waiting).
- Keep `MAILBATCH_WORK_SECONDS` below PHP `max_execution_time` (30 s on many hosts).
- Use `php artisan serve` with `PHP_CLI_SERVER_WORKERS=4` (already in `.env`) so the page can poll while a work request runs.
- Do not run a separate `queue:work` for `mailbatch-c*` queues; it is not needed.

## 19. Run directly from a URL path (no `artisan serve`)

Put the project folder in `htdocs` (XAMPP) or your hosting web folder, e.g. `htdocs/mailbatch`, and open
`http://localhost/mailbatch`. The `index.php` and `.htaccess` in the project root forward requests to `public/` and serve
`public/assets`. Needs Apache `mod_rewrite` with `AllowOverride All`. Set `APP_URL=http://localhost/mailbatch`.
Only database setup (`migrate` / seed) is a one-time job; import it once or run it once from a terminal.
